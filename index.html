MODULE 01 / 14

C'est quoi un microcontrôleur ?

Objectifs :
  • Définir un microcontrôleur avec tes propres mots
  • Comprendre pourquoi la carte Arduino est l'outil idéal pour apprendre

Un microcontrôleur (µC), c'est un ordinateur complet miniaturisé sur une seule puce : un processeur, de la mémoire et des broches d'entrées/sorties, pour quelques euros.

Contrairement à un PC, il ne sert pas à tout faire. Il est programmé pour une seule mission, qu'il répète des millions de fois par seconde, sans écran ni clavier : surveiller un capteur, piloter une électrovanne, compter des impulsions. Sans programme, c'est le composant le plus inutile du monde ; avec le bon programme, c'est le plus polyvalent.

⛏ Sur le terrain Une foreuse DP1500i contient des dizaines de microcontrôleurs : modules du bus CAN, afficheurs, capteurs intelligents. Quand tu diagnostiques un module qui « ne répond plus », tu diagnostiques un microcontrôleur et son programme.

Pourquoi apprendre avec Arduino ?

Arduino est une petite carte électronique open source née en 2005, construite autour d'un microcontrôleur AVR (l'ATmega328 sur la carte UNO). Elle a été pensée pour que n'importe qui puisse débuter : la carte coûte une dizaine d'euros, le logiciel est gratuit, et la communauté mondiale partage des milliers d'exemples.

Surtout, Arduino enlève tout ce qui décourage les débutants : pas de soudure pour commencer, pas de programmateur spécial, pas de configuration obscure. Tu branches la carte en USB, tu écris ton programme, tu cliques sur un bouton — et ta LED clignote. C'est la carte que nous utiliserons pour tous les TP de ce cours.

La plaque d'essai en 20 secondes

Les trous d'une même rangée de 5 sont reliés entre eux ; les deux colonnes latérales (+ et −) courent sur toute la longueur — on y amène le 5 V et le GND de l'Arduino. Un composant enfiché sur deux rangées différentes se retrouve « câblé » sans soudure.

Les 3 règles qui sauvent tes composants

1. Une LED a toujours sa résistance. Sans elle, le courant n'est pas limité : la LED grille (et parfois la broche avec). 220 Ω est la valeur passe-partout en 5 V. C'est la loi d'Ohm au travail : U = R × I — la résistance limite le courant à une vingtaine de milliampères.

2. Les masses (GND) sont toujours communes. Deux circuits qui dialoguent doivent partager la même référence 0 V. Sinon les signaux n'ont aucun sens — exactement comme sur les machines.

3. Une broche fournit quelques milliampères, pas plus. LED : oui. Moteur, relais, bobine : jamais en direct — il faut un transistor ou un module relais entre les deux (l'« interface de puissance » qu'on verra au module 5).

⛏ Sur le terrain Ces trois règles, tu les appliques déjà en électromécanique : calibre des protections, équipotentielle des masses, relayage des commandes. L'Arduino, c'est la même logique en miniature — 5 V au lieu de 24 V, milliampères au lieu d'ampères.

Quiz express

1. Pourquoi une résistance en série avec chaque LED ?
U = R × I : sans résistance, le courant s'emballe et détruit la LED. 220 Ω sous 5 V ≈ 20 mA, parfait.
2. Un capteur externe alimenté séparément envoie un signal incohérent à l'Arduino. Premier réflexe ?
Sans référence commune, un signal n'a pas de sens. C'est le premier point de contrôle, sur une plaque d'essai comme sur une foreuse.
MODULE 03 / 14

Ton premier programme : la LED qui clignote

Objectifs :
  • Installer l'IDE Arduino et téléverser un programme
  • Comprendre la structure setup() / loop()

Le rite d'initiation de tout l'embarqué : faire clignoter une LED. C'est le « bonjour le monde » du matériel — et c'est le moment où le débutant réalise qu'il vient de donner un comportement à un objet.

La chaîne de travail

1. Tu écris le programme (le sketch) dans l'IDE Arduino sur PC.
2. Tu branches la carte en USB et tu choisis carte + port dans le menu Outils.
3. Tu cliques Téléverser : l'IDE compile ton code et l'écrit dans la mémoire Flash du µC.
4. La carte exécute ton programme immédiatement — et à chaque remise sous tension, pour toujours, jusqu'au prochain téléversement.

Le squelette universel : setup() et loop()

// Tout sketch Arduino a exactement cette structure :
void setup() {
  // exécuté UNE FOIS au démarrage : les réglages
}

void loop() {
  // exécuté EN BOUCLE, sans fin : le travail
}

Un programme embarqué ne se termine jamais : après l'initialisation, il tourne tant que la carte est alimentée. loop() est rappelée automatiquement dès qu'elle finit — c'est la boucle infinie « lire → décider → agir » qui fait vivre toutes les machines.

🔧 TP 1 — À toi de jouer : Blink

Aucun câblage : la carte UNO a une LED intégrée sur la broche 13. Téléverse ceci :

void setup() {
  pinMode(13, OUTPUT);          // broche 13 en sortie
}

void loop() {
  digitalWrite(13, HIGH);       // LED allumée
  delay(500);                    // attendre 500 ms
  digitalWrite(13, LOW);        // LED éteinte
  delay(500);
}

Puis expérimente — c'est là que l'apprentissage se fait : change les durées (100 ms ? 2000 ms ?), fais deux clignotements rapides puis une pause, ajoute une vraie LED (+ résistance 220 Ω) entre la broche 8 et GND et pilote-la aussi.

✔ Erreurs classiques de débutant Le point-virgule oublié en fin de ligne (le compilateur proteste — lis son message, il indique la ligne). Le mauvais port sélectionné (rien ne se téléverse). La LED à l'envers (la patte courte va vers GND). Aucune n'est grave : on corrige, on re-téléverse, c'est fait pour ça.

Quiz express

1. Dans quel ordre s'exécutent setup() et loop() ?
setup() = les réglages au démarrage ; loop() = le travail, répété tant que la carte est alimentée.
2. Que devient ton programme quand tu débranches la carte ?
La Flash est non volatile : le programme survit aux coupures. C'est ce qui rend le µC autonome.
MODULE 04 / 14

Le binaire et l'hexadécimal

Objectifs :
  • Convertir entre binaire, décimal et hexadécimal
  • Comprendre le bit, l'octet, et le poids des bits

Ton HIGH et ton LOW du TP 1, c'était déjà du binaire ! Un microcontrôleur ne connaît que deux états : 0 (tension basse, ~0 V) et 1 (tension haute, 5 V). Toute l'information — nombres, textes, commandes — est codée avec ces deux chiffres.

⛏ Sur le terrain Un contacteur est enclenché ou pas. Une électrovanne est excitée ou pas. Le binaire, c'est la logique tout-ou-rien de l'électromécanique que tu pratiques déjà tous les jours.

Le poids des bits

Chaque position dans un nombre binaire a un poids qui double à chaque rang : 1, 2, 4, 8, 16, 32, 64, 128. Pour convertir en décimal, on additionne les poids des bits à 1. Exemple : 1011 = 8 + 0 + 2 + 1 = 11.

Manipule un registre 8 bits 👇

Touche les cases pour basculer les bits et observe la valeur changer :

Décimal 0 Hexa 0x00 Binaire 0b00000000
8 bits = 1 octet → valeurs de 0 à 255. C'est exactement une case mémoire de µC.

Pourquoi l'hexadécimal ?

Écrire 11110100 est pénible et source d'erreurs. L'hexadécimal (base 16) regroupe les bits par paquets de 4 : chaque paquet devient un chiffre de 0 à F. 1111 0100 = 0xF4. Deux caractères au lieu de huit — c'est la notation des datasheets et des trames CAN que tu liras au diagnostic. À retenir : 0xFF = 255 = l'octet plein.

Quiz express

1. Combien vaut 0b00000101 en décimal ?
Bits à 1 aux poids 4 et 1 → 4 + 1 = 5.
2. 0xFF correspond à…
F = 15 → 15×16 + 15 = 255 = 11111111 : l'octet plein.
MODULE 05 / 14

L'architecture d'un système à microcontrôleur

Objectifs :
  • Situer chaque bloc : µP, mémoires, timers, CAN/CNA, interfaces
  • Comprendre la chaîne complète : capteur → µC → interface de puissance → actionneur

Un système à microcontrôleur, ce n'est pas seulement la puce : c'est toute une chaîne. Au centre, le microprocesseur (µP), entouré de ses blocs, qui dialogue avec le monde extérieur.

Le µP : le chef d'orchestre

À l'intérieur, une unité de calcul (l'ALU et ses registres, qui exécutent les opérations) et une unité de contrôle (qui supervise le déroulement de toutes les opérations), reliées par le bus. Le quartz et l'oscillateur donnent le battement de cœur : 16 millions de tics par seconde sur un UNO. Le reset ramène tout au point de départ.

Au fait — les circuits du µP sont bâtis avec des portes logiques que tu connais sans le savoir : la porte ET, c'est des contacts en série ; la porte OU, des contacts en parallèle ; et la mémoire élémentaire (la bascule), c'est l'auto-maintien d'un contacteur. L'électronique numérique, c'est ton schéma électrique en millions d'exemplaires microscopiques.

Les mémoires

MémoireContenuÀ la coupure ?
Flash (la ROM moderne)Ton programmeConservé
RAMLes variables pendant l'exécutionPerdu
EEPROMPetites données à garder (réglages, compteurs)Conservé
⛏ Sur le terrain Un module de foreuse qui perd ses paramètres après un remplacement de batterie : ils étaient en RAM. Les compteurs horaires qui survivent : EEPROM ou Flash. Ce détail change ta procédure de remplacement de module.

CAN et CNA : les ponts entre deux mondes

Le CAN (Convertisseur Analogique-Numérique, ADC en anglais) traduit une tension en nombre : c'est lui qui permet de lire un capteur analogique. Le CNA (DAC) fait l'inverse : d'un nombre vers une tension.

✔ Attention au vocabulaire En français, CAN désigne le convertisseur A/N… mais aussi le bus CAN des véhicules et engins ! Deux choses totalement différentes, même sigle. « Le CAN du capteur » = convertisseur ; « le bus CAN de la machine » = réseau. Le contexte tranche toujours.

La chaîne complète

Côté sortie : µC → driver PWM → interface de puissance (transistors, relais) → actionneur. Côté entrée : élément à mesurer → capteur → (CAN si analogique) → µC. Tout système embarqué est une variation de cette chaîne.

Quiz express

1. Quelle mémoire garde ton programme après une coupure de courant ?
La Flash est non volatile : ton Blink du module 3 y vit toujours.
2. Le µC doit piloter un moteur de plusieurs ampères. Il lui faut…
Une broche fournit quelques mA : sans transistor/relais, elle grille. Règle n°3 du module 2.
MODULE 06 / 14

Capteurs et actionneurs

Objectifs :
  • Définir capteur et actionneur
  • Classer les capteurs : analogiques, numériques, logiques

Le µC perçoit le monde par ses capteurs et agit dessus par ses actionneurs. Toute la suite du cours consiste à apprendre à les brancher et à les programmer.

Le capteur : percevoir

Un capteur transforme une grandeur physique (température, pression, lumière…) en une grandeur électrique exploitable. On les classe en trois groupes selon leur signal de sortie :

TypeSignal de sortieExemplesLecture Arduino
Logique (TOR)Tout Ou Rien : 0 ou 1Bouton, fin de course, pressostatdigitalRead()
AnalogiqueTension continûment variablePotentiomètre, LDR, capteur de gaz MQ-2, transducteur de pressionanalogRead() (via le CAN)
NumériqueDonnées codées (trames)DHT11 (température/humidité), capteurs I2C/SPIBibliothèque + bus de communication
⛏ Sur le terrain Sur une foreuse tu as les trois : fins de course et pressostats (logiques), transducteurs de pression (analogiques), capteurs « intelligents » sur le bus (numériques). Identifier le type, c'est savoir où et comment mesurer au diagnostic.

L'actionneur : agir

Les actionneurs transforment l'énergie en phénomène physique : mouvement (moteurs, servos, électrovannes), chaleur (résistances), lumière (LEDs, afficheurs), son (buzzers). Rappel de la règle n°3 : au-delà de quelques milliampères, jamais en direct sur la broche — transistor ou relais obligatoire.

✔ À retenir La chaîne se lit dans les deux sens : grandeur physique → capteur → µC → interface de puissance → actionneur → action. Exemple complet : un basculement automatique entre deux sources d'énergie — capteurs de tension en entrée, décision dans le µC, contacteurs en sortie. C'est la chaîne du module 5, appliquée telle quelle.

Quiz express

1. Un bouton poussoir est un capteur…
Deux états, appuyé ou relâché : lu avec digitalRead().
2. Un capteur de gaz MQ-2 sort une tension variable. On le lit avec…
Signal analogique → conversion en nombre obligatoire avant traitement.
MODULE 07 / 14

Entrées / sorties : LED et bouton

Objectifs :
  • Piloter une sortie et lire une entrée
  • Comprendre le pull-up et pourquoi une entrée « en l'air » ment

Les broches GPIO sont les mains du microcontrôleur. Trois fonctions Arduino suffisent pour tout le tout-ou-rien :

FonctionRôleAnalogie
pinMode(broche, mode)Choisir : entrée ou sortieLe sélecteur du multimètre
digitalWrite(broche, HIGH/LOW)Écrire une sortieL'interrupteur de commande
digitalRead(broche)Lire une entréeLa lecture au voltmètre

Le piège de l'entrée « en l'air »

Une entrée reliée à rien n'est ni à 0 ni à 1 : elle flotte et capte les parasites — la lecture devient aléatoire. Il faut lui imposer un état de repos avec une résistance de pull-up (vers le +) ou pull-down (vers la masse). Bonne nouvelle : l'Arduino a des pull-ups internes, activées par pinMode(2, INPUT_PULLUP) — le bouton se câble alors simplement entre la broche et GND, et la logique s'inverse : appuyé = LOW.

⛏ Sur le terrain Un fil de commande débranché « flotte » et déclenche des défauts fantômes intermittents. Face à un signal incohérent, vérifie toujours si l'entrée a bien son potentiel de référence — sur breadboard comme sur machine.
🔧 TP 2 — Le bouton qui commande la LED

Montage : LED + résistance 220 Ω entre broche 8 et GND. Bouton entre broche 2 et GND (pull-up interne, pas d'autre composant).

void setup() {
  pinMode(8, OUTPUT);
  pinMode(2, INPUT_PULLUP);       // bouton vers GND
}

void loop() {
  if (digitalRead(2) == LOW) {   // appuyé (logique inversée)
    digitalWrite(8, HIGH);
  } else {
    digitalWrite(8, LOW);
  }
}

Expérimente : inverse le comportement (LED allumée au repos), puis fais un télérupteur : un appui allume, l'appui suivant éteint (indice : il faut mémoriser un état dans une variable — et tu découvriras le phénomène de rebond du bouton !).

✔ Pour aller plus loin (les registres) Sous le capot, digitalWrite() écrit un bit dans un registre du port (sur AVR : DDRx pour la direction, PORTx pour l'écriture, PINx pour la lecture). C'est ce que font tous les µC industriels, Arduino ou pas — utile à savoir quand tu liras une datasheet, inutile à manipuler pour débuter.

Quiz express

1. Avec INPUT_PULLUP et un bouton câblé vers GND, un appui se lit…
Le pull-up tient la broche à HIGH au repos ; l'appui la relie à la masse → LOW. Logique inversée, très courante.
2. Une entrée laissée « en l'air » donne une lecture…
Sans référence, la broche flotte : d'où les pull-up/pull-down.
MODULE 08 / 14

Programmer en clair : variables, décisions, répétitions

Objectifs :
  • Utiliser variables, conditions et boucles
  • Se servir du moniteur série : les yeux du programme

Programmer, c'est écrire une histoire que le µC va vivre comme sa seule réalité. Et cette histoire tient avec trois briques : retenir (variables), décider (conditions), répéter (boucles).

Les trois briques

// RETENIR : une variable est une case mémoire nommée
int seuil = 300;
int mesure = 0;

// DÉCIDER : if / else
if (mesure > seuil) {
  digitalWrite(8, HIGH);     // alarme
} else {
  digitalWrite(8, LOW);
}

// RÉPÉTER : for
for (int i = 0; i < 3; i++) {
  digitalWrite(8, HIGH); delay(100);
  digitalWrite(8, LOW);  delay(100);
}

Et pour ranger : une fonction regroupe des lignes sous un nom (clignoter(3); est plus lisible que dix lignes répétées). Tu en utilises déjà : digitalWrite() est une fonction écrite par d'autres.

Le moniteur série : les yeux de ton programme

Le µC n'a pas d'écran — mais il peut parler à ton PC par le câble USB. C'est l'outil de mise au point n°1, celui que tu ouvriras à chaque TP :

void setup() {
  Serial.begin(9600);              // ouvrir la liaison, 9600 bauds
}

void loop() {
  Serial.print("Mesure : ");
  Serial.println(mesure);           // affiche + retour à la ligne
  delay(500);
}
⛏ Sur le terrain La boucle « lire → décider → agir » est ta démarche de diagnostic : mesurer, comparer au seuil, intervenir. Et le moniteur série, c'est ta valise de diagnostic branchée sur la machine : il te montre ce que le programme « pense ».
🔧 TP 3 — Compteur d'appuis

Reprends le montage du TP 2 et affiche au moniteur série le nombre d'appuis sur le bouton. Indice : une variable int compteur = 0; déclarée avant setup(), incrémentée avec compteur = compteur + 1; à chaque appui détecté. Bonus : ajoute delay(200); après la détection et observe pourquoi ça compte mieux (le rebond, encore lui).

Quiz express

1. À quoi sert Serial.println() ?
C'est l'outil de mise au point fondamental : le programme te raconte ce qu'il vit.
2. Que fait ce code : for (int i = 0; i < 5; i++) { clignoter(); } ?
i prend les valeurs 0,1,2,3,4 : cinq passages dans la boucle.
MODULE 09 / 14

Maîtriser le temps : delay(), millis() et le chien de garde

Objectifs :
  • Comprendre pourquoi delay() bloque tout
  • Clignoter sans bloquer avec millis()
  • Connaître le rôle du chien de garde

Jusqu'ici, delay() nous suffisait. Mais il a un défaut grave : pendant l'attente, le µC ne fait rien d'autre. Plus de lecture de bouton, plus de surveillance de capteur, plus de sécurité.

⛏ Sur le terrain delay(), c'est le mécano qui fixe le chrono en attendant que l'huile chauffe. millis(), c'est celui qui règle une minuterie et continue son inspection. Un système de sécurité ne doit jamais fixer le chrono.

millis() : l'horloge qui tourne toute seule

Grâce aux timers matériels du µC (des compteurs qui avancent en arrière-plan, sans occuper le processeur), la fonction millis() te donne à tout instant le nombre de millisecondes écoulées depuis le démarrage. La recette du « clignoter sans bloquer » :

unsigned long dernierTop = 0;
bool etatLed = false;

void loop() {
  if (millis() - dernierTop >= 500) {   // 500 ms écoulées ?
    dernierTop = millis();               // noter l'heure du top
    etatLed = !etatLed;                  // inverser
    digitalWrite(13, etatLed);
  }
  // ...et ici, le programme reste LIBRE de faire autre chose !
  if (digitalRead(2) == LOW) { /* réagir au bouton immédiatement */ }
}

Le chien de garde (watchdog)

Autre service rendu par un timer : le chien de garde redémarre le µC si le programme reste bloqué. En fonctionnement normal, le programme « caresse le chien » régulièrement (il remet un compteur à zéro) ; s'il cesse de le faire — programme planté, boucle sans sortie — le chien mord : reset automatique. C'est l'assurance-vie des systèmes qui doivent tourner sans surveillance.

⛏ Sur le terrain Un module de foreuse qui redémarre tout seul de façon répétée : c'est peut-être son chien de garde qui mord parce que le programme se bloque (souvent sur une communication qui ne répond pas). Le redémarrage est le symptôme, pas la panne.
🔧 TP 4 — Clignoter ET surveiller en même temps

Monte LED (broche 8) + bouton (broche 2, INPUT_PULLUP). Objectif : la LED 13 clignote toutes les 500 ms pendant que la LED 8 suit le bouton instantanément. Essaie d'abord avec delay() pour constater le problème (le bouton répond mal), puis avec millis() : tout devient fluide. Tu viens de comprendre pourquoi tout l'embarqué industriel bannit les attentes bloquantes.

Quiz express

1. Le problème de delay(2000) dans un système de surveillance :
delay() gèle tout le programme. millis() permet d'attendre sans bloquer.
2. Un µC redémarre automatiquement quand son programme se bloque. Qui agit ?
Le watchdog n'est plus « caressé » → il force un reset. Symptôme classique : des redémarrages en boucle.
MODULE 10 / 14

Les interruptions : réagir immédiatement

Objectifs :
  • Comprendre le mécanisme d'interruption
  • Utiliser attachInterrupt() pour un événement urgent

Vérifier le bouton à chaque tour de loop(), ça marche… tant que loop() tourne vite. Une interruption renverse la logique : c'est l'événement qui prévient le processeur, qui suspend alors le programme, exécute une petite routine dédiée, puis reprend exactement où il en était.

⛏ Sur le terrain Vérifier en boucle, c'est aller voir la machine toutes les 5 minutes. L'interruption, c'est le voyant qui bipe dès le défaut. Pour un arrêt d'urgence, il n'y a pas débat : réaction immédiate obligatoire.

En Arduino : attachInterrupt()

Sur un UNO, les broches 2 et 3 acceptent les interruptions externes :

volatile bool urgence = false;

void alerte() {                    // la routine d'interruption : COURTE
  urgence = true;                  // on lève juste un drapeau
}

void setup() {
  pinMode(2, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(2), alerte, FALLING);
}                                   // FALLING = front descendant (appui)

void loop() {
  if (urgence) {                   // le traitement se fait ICI
    toutArreter();
    urgence = false;
  }
  travailNormal();
}
✔ Les deux règles d'or 1. La routine reste courte : lever un drapeau, noter une valeur, sortir. Le vrai traitement se fait dans loop().
2. volatile est obligatoire sur toute variable partagée avec la routine : ce mot-clé dit au compilateur « cette variable peut changer à tout instant, relis-la vraiment en mémoire ».

Quiz express

1. Une bonne routine d'interruption doit être…
Pendant la routine, le reste du programme est suspendu : minimum d'actions, et surtout jamais d'attente.
2. Pourquoi volatile sur le drapeau partagé ?
Sans volatile, le compilateur peut « optimiser » la lecture et ne jamais voir le changement fait par l'interruption.
MODULE 11 / 14

Le PWM : doser la puissance

Objectifs :
  • Comprendre le rapport cyclique
  • Utiliser analogWrite() pour varier une intensité

Une broche ne sait produire que 0 ou 5 V — tout ou rien. Comment alors tamiser une LED ou ralentir un moteur ? En commutant très vite : c'est le PWM (modulation de largeur d'impulsion). La valeur moyenne perçue dépend du rapport cyclique : le pourcentage du temps passé à l'état haut.

Essaie toi-même 👇

Rapport cyclique : 50 % → tension moyenne : 2,5 V (sur 5 V)

En Arduino : analogWrite()

Sur les broches marquées ~ (3, 5, 6, 9, 10, 11 sur un UNO) :

analogWrite(9, 0);      // 0 % : éteint
analogWrite(9, 127);    // ~50 % : demi-intensité
analogWrite(9, 255);    // 100 % : pleine puissance

La valeur va de 0 à 255 (un octet — tu reconnais le module 4 !). Malgré son nom, analogWrite() ne produit pas une vraie tension analogique : c'est bien du découpage PWM.

⛏ Sur le terrain Les électrovannes proportionnelles des circuits hydrauliques (rotation, avance, percussion) sont pilotées en PWM : le module fait varier le rapport cyclique → courant dans la bobine → ouverture du tiroir → débit. Un signal « carré » mesuré sur une bobine Y601 au lieu d'un continu propre : c'est normal, c'est du PWM. Et l'avantage est énorme : un transistor tout-ou-rien ne chauffe presque pas.
🔧 TP 5 — Respiration lumineuse

LED + résistance sur la broche 9. Fais-la « respirer » : deux boucles for qui font monter puis descendre la valeur d'analogWrite() de 0 à 255 et retour, avec un petit delay(5) à chaque pas. Bonus : remplace les delay() par la technique millis() du module 9.

Quiz express

1. analogWrite(broche, 51) sur 5 V donne une moyenne d'environ…
51/255 = 20 % de rapport cyclique → 5 × 0,20 = 1 V de moyenne.
2. Pourquoi piloter une électrovanne proportionnelle en PWM plutôt qu'en tension variable ?
Un transistor en régime linéaire chaufferait énormément ; en commutation il dissipe presque rien.
MODULE 12 / 14

Lire l'analogique : analogRead() et le CAN

Objectifs :
  • Lire une tension avec analogRead()
  • Convertir une lecture en grandeur physique (mise à l'échelle)

Le monde réel est analogique : une pression, une température, une lumière varient continûment. Le CAN du µC (module 5) transforme la tension en nombre — et sur Arduino, une seule fonction suffit : analogRead().

La résolution : 1024 paliers

Le CAN de l'UNO travaille sur 10 bits : il découpe 0–5 V en 2¹⁰ = 1024 paliers. analogRead(A0) renvoie donc un nombre de 0 à 1023 : 0 pour 0 V, 1023 pour 5 V, 512 pour ~2,5 V.

✔ Formule de mise à l'échelle Tension = lecture × 5.0 / 1023. Et pour passer à la grandeur physique, on applique la caractéristique du capteur. Exemple, capteur de pression 0,5–4,5 V pour 0–250 bar :
float bar = (volts - 0.5) * 250.0 / 4.0;
⛏ Sur le terrain Les transducteurs de pression des foreuses (B601P, B603P…) sortent 0,5–4,5 V ou 4–20 mA. La plage décalée est volontaire : si tu lis 0 V pile, ce n'est pas une pression nulle — c'est un fil coupé. Le décalage transforme la panne en diagnostic. Retiens ce réflexe : 0 V sur un capteur 0,5–4,5 V = circuit ouvert.
🔧 TP 6 — Potentiomètre et veilleuse automatique

Étape 1 : potentiomètre sur A0 (pattes extrêmes sur 5 V et GND, curseur sur A0). Affiche la valeur au moniteur série et tourne : tu vois défiler 0 → 1023.

int brut = analogRead(A0);
float volts = brut * 5.0 / 1023.0;
Serial.println(volts);

Étape 2 : remplace le potentiomètre par une LDR en pont diviseur avec une résistance de 10 kΩ, et pilote la LED : allumée quand il fait sombre (lecture sous un seuil). Tu viens de construire une veilleuse automatique — capteur → décision → actionneur, la chaîne complète.

Quiz express

1. analogRead() renvoie 1023. La tension d'entrée est…
1023 est la valeur maximale du CAN 10 bits : l'entrée est à la tension de référence.
2. Un capteur 0,5–4,5 V renvoie 0 V. Diagnostic le plus probable :
La plage décalée sert exactement à ça : 0 V est hors fonctionnement normal → défaut de câblage.
MODULE 13 / 14

Communiquer : du câble USB au bus CAN

Objectifs :
  • Comprendre le principe des liaisons série
  • Distinguer UART, I2C, SPI et le bus CAN

Un µC seul, c'est bien. Des µC qui se parlent, c'est une machine moderne. Les liaisons série envoient les bits un par un sur quelques fils — et tu en utilises déjà une depuis le module 8 : Serial, c'est l'UART de la carte.

Les quatre protocoles à connaître

ProtocoleFilsUsage typiquePoint fort
UART (Serial)2 (TX/RX)Moniteur série, GPS, BluetoothSimplicité
I2C (Wire)2 (SDA/SCL)Capteurs, écrans, RTCPlusieurs modules sur 2 fils
SPI4Cartes SD, écrans rapidesVitesse
Bus CAN2 (CAN-H/CAN-L)Véhicules, engins miniersRobuste aux parasites, priorités

Règle d'or de l'UART : même vitesse des deux côtés (le baudrate — 9600 dans nos TP). Des caractères illisibles au moniteur = baudrates différents. C'est le premier réflexe de dépannage.

Le bus CAN : le roi de l'industriel

Attention au sigle : ici, CAN = Controller Area Network, le réseau — rien à voir avec le convertisseur du module 12. Ce bus utilise une paire différentielle (CAN-H / CAN-L) : le récepteur lit la différence entre les deux fils, donc un parasite qui touche les deux fils en même temps s'annule. Chaque trame porte un identifiant qui fixe sa priorité : les messages critiques passent toujours devant. Le bus est terminé par deux résistances de 120 Ω.

⛏ Sur le terrain Le bus CAN d'une DP1500i relie des dizaines de microcontrôleurs sur une simple paire torsadée. Tout ce que tu as appris — broches, ADC, PWM, interruptions — tourne dans chacun de ces modules. Comprendre le µC, c'est comprendre la machine. (Et le coup des 120 Ω : deux résistances de terminaison en parallèle → tu dois mesurer ≈ 60 Ω entre CAN-H et CAN-L bus hors tension. Mesure de base du diagnostic CAN.)

Quiz express

1. Le moniteur série affiche des caractères illisibles. Cause probable :
L'UART n'a pas d'horloge partagée : même vitesse obligatoire des deux côtés. (Le 120 Ω, c'est pour le bus CAN !)
2. Pourquoi le bus CAN résiste-t-il si bien aux parasites d'un engin minier ?
Un parasite induit la même tension sur CAN-H et CAN-L ; la différence, elle, ne bouge pas.
MODULE 14 / 14

Projet final : la mini station de surveillance

Objectifs :
  • Assembler tout le cours dans un vrai petit système
  • Découvrir la machine à états : le patron de tout l'embarqué industriel

Un système complet, avec le matériel des TP : une LDR (le capteur), une LED verte et une LED rouge + buzzer (les actionneurs), un bouton d'acquittement. Mission : surveiller la lumière et donner l'alarme si elle passe sous un seuil — comme un capteur de flamme, de niveau ou de présence sur une machine.

L'outil des pros : la machine à états

Plutôt qu'un empilement de if, on décrit le système comme une machine à états : une liste d'états possibles et des transitions déclenchées par des événements. Notre station en a trois :

ÉtatComportementTransition
SURVEILLANCELED verte allumée, on mesureLumière sous le seuil → ALARME
ALARMELED rouge clignote (millis() !), buzzerAppui bouton → ACQUITTÉ
ACQUITTÉSilence, rouge fixeLumière revenue au-dessus du seuil → SURVEILLANCE
enum { SURVEILLANCE, ALARME, ACQUITTE } etat = SURVEILLANCE;

void loop() {
  int lumiere = analogRead(A0);
  switch (etat) {
    case SURVEILLANCE:
      if (lumiere < 300) etat = ALARME;
      break;
    case ALARME:
      // rouge clignote + buzzer (avec millis, pas delay !)
      if (digitalRead(2) == LOW) etat = ACQUITTE;
      break;
    case ACQUITTE:
      if (lumiere > 400) etat = SURVEILLANCE;
      break;
  }
}

Remarque le double seuil (300 / 400) : cet écart, c'est l'hystérésis — il évite que le système batte entre deux états quand la mesure hésite autour du seuil. Exactement comme un pressostat.

⛏ Sur le terrain Une séquence de forage est une machine à états : ARRÊT → PRÉ-LUBRIFICATION → ROTATION → PERCUSSION. Une machine « bloquée » dans une phase, c'est une condition de transition jamais satisfaite — souvent un capteur HS. Réflexe : identifier la condition attendue par l'état bloqué, puis tester le capteur correspondant. Ce patron variable d'état + switch, tu viens de l'écrire toi-même : c'est le même qui tourne dans les modules de la foreuse.
🔧 TP 7 — Construis la station

Assemble et programme la station complète. Étapes conseillées : 1) la mesure seule avec affichage série (module 12) ; 2) l'état SURVEILLANCE/ALARME sans le bouton ; 3) l'acquittement ; 4) le clignotement non bloquant. Quand ça marche : ajoute un compteur d'alarmes affiché au moniteur, puis mémorise-le en EEPROM pour qu'il survive aux coupures. Tu utilises alors chaque module de ce cours.

✔ Et après ? Tu as les fondations : le reste (écrans, moteurs, capteurs I2C, modules radio…) s'apprend de la même façon — un montage simple, un exemple, le moniteur série, et de l'expérimentation. La progression logique : servomoteurs et écrans LCD, puis capteurs numériques (DHT11), puis un projet utile chez toi ou à l'atelier. Chaque nouveau composant réutilise les mêmes fondations.

Quiz express

1. À quoi sert l'hystérésis (double seuil) ?
Un seul seuil = battements incessants autour de la limite. Deux seuils écartés = comportement stable. Comme un pressostat.
2. Dans une machine à états, une machine « bloquée » dans une phase signifie généralement…
Réflexe diagnostic : identifier la condition attendue par l'état bloqué, puis vérifier le capteur ou signal correspondant.
